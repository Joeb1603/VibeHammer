## D-088: Visibility with terrain: Obscuring, Solid in 2D, Hidden and Fully Visible (13.07, 13.09–13.11, 06.01; extends D-017)
**Decided:** 2026-11-12 (M88's plan mode; design approved by the user). **Implemented:** M88 (see "In code" below).
Builds on D-087's 2D model and D-017's line of sight; D-009 gives "within".

- **Within a terrain area** (D-009): any part of the base is within the area: the signed distance between the base and
  the area's shape is at most EPS_MM. Circles use the round kernel (an area as a round "base", as D-084 measures
  objectives); polygons use D-074's GJK, whose `Convex` gains a convex polygon support.
- **What terrain blocks a line of sight.** 06.01's line is 1 mm wide; a terrain shape blocks it when the line's centre
  comes within 0.5 mm − EPS_MM of the shape (the strip overlaps it by more than EPS_MM), exactly as D-017 treats a
  model base. Two kinds of shape block, in addition to the models D-017 already counts:
  - **13.10 Obscuring.** Every area holding one or more Light or Dense features, except an area that the observing
    model or the observed model is within. If every line of sight crosses one, the two models are not visible to each
    other.
  - **13.11 Solid, in 2D.** Every Dense feature, wholly, whichever area either model is in. 13.11 lets lines through
    enclosed gaps more than 3" from ground level; with no z, the whole footprint counts as the part 3" or less from
    ground level (`TODO(z)`).
- **Candidate lines.** D-017's (centre to centre, sample pairs, common tangents of the circles), plus the common
  tangents that involve each blocking polygon's vertices (taken as 0.5 mm circles, the corners of the inflated polygon)
  and each blocking circle. Only shapes near the hull of the two bases are tested; with none near, the old code runs
  unchanged, so terrain-free results stay bit-identical. Like D-017, this is not a proof of exactness.
- **13.09 Hidden.** A model is hidden while all of the following apply:
  - it has the INFANTRY, BEASTS or SWARM keyword;
  - it is within a terrain area that holds one or more Dense features;
  - its unit made no ranged attacks during this turn or the previous turn.

  A hidden model can be visible only to enemy models within its detection range, 15" (`kDetectionRangeMm`, edge to
  edge, D-009 within), and then only if a line of sight exists.
- **The record behind Hidden.** `Unit::ranged_attacks {this_turn, previous_turn}`. A Shoot action with one or more
  declarations sets `this_turn` (close-quarters shooting counts: those are ranged attacks). Leaving the End of Turn
  step, `previous_turn` takes `this_turn` and `this_turn` clears, so a unit that shoots in its own turn is not hidden
  for the rest of that turn and all of the opponent's next turn. The record is kept only on a battlefield with terrain,
  the only place 13.09 reads it; JSON `"ranged_attacks"`, omitted when both are false.
- **06.01 Fully Visible, for 13.08.** "Every part of another model that is facing the observing model" is, in 2D, the
  boundary points of the observed base whose outward normal points towards the observing model's centre (the half
  circle facing it, for a round base). That part is sampled at 9 points, both ends inside the half. The model is fully
  visible when every sampled point can be reached by a 1 mm line from some part of the observing model past the
  *intervening terrain*:
  - Light and Dense features, and obscuring areas other than those either model is within (13.10's exclusion, which
    13.08 points to with "see below");
  - models do not count: 13.08 asks whether the model is not fully visible "due to" terrain.

  The candidate lines for a point are those to the observer's 33 D-017 sample points and the tangents from the point
  through the blockers' vertices. Not a proof of exactness.
- **Unit level** (06.01) is unchanged: a unit is visible if one or more of its models are visible.

**In code (M88).**
- **Queries.** `rules/terrain.hpp`:
  - `is_hidden` and `model_visible`, which applies the 15" detection range edge to edge (D-009 within) before any line
    of sight;
  - `visibility_problem`, which gives 13.09, then "13.10 / 13.11" when a line exists without terrain, then 06.01. The
    engine's refusal text, the client's hover text and the arena's counts all use it.
  - A per-state `TerrainView` caches each model's areas (a 32-bit mask) and the blocker lists per pair of masks.
- **Blockers for a pair of models.** The obscuring areas neither model is within, plus the Dense features of the areas
  either is within. A Dense feature of any other area is inside that obscuring area, which blocks every line the
  feature would, because features lie wholly within their areas, exactly. A test checks this on the terrain scenario.
  For Fully Visible, the same with the Light features too.
- **Line of sight** (`visibility_oval.cpp`, beside D-074's kernel): the terrain overload of `has_line_of_sight`.
  - With no terrain shape within the bases' reach of the centre-to-centre segment it returns the old answer.
  - Otherwise it tries the centre line first.
  - Then an exact early "no": a shape that misses both bases' bounding circles but crosses both outer common tangents
    of those circles cuts every line between them.
  - Then D-017's candidates plus the tangents through each near polygon vertex (a 0.5 mm circle) and each widened
    terrain circle.
  - New sample points use the deterministic `sin_cos_deg`.
- **Fully Visible.** `fully_visible_past` samples the facing half's outward normals every 20 degrees from -80 to 80.
  For each sample it tries the lines to the observer's sample points and the tangents from the point through each
  blocker vertex or circle.
- **The record.** `Unit::ranged_attacks` (JSON `"ranged_attacks"`, omitted when both are false) is set by a Shoot and
  rolled on leaving the End of Turn step, only on a battlefield with terrain.
- **Without terrain** every query takes the old code (`TargetFacts` checks `state.terrain.empty()`), so every old
  replay and the bot's identity set are unchanged.
