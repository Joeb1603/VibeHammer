## D-014: Event log and replay files (engine design)
**Decided:** 2026-11-02 (M5 plan)
- `apply_action` returns the events it caused. They are not stored in `GameState` (saves stay small);
  the `Match` class keeps the running event log, the initial state and the action list.
- A replay file (`tests/replays/*.json`, format 1) holds `initial` (either `{scenario, seed}` or a
  full `{state}`), the `(side, action)` steps, and an `expect` block (result, stage, battle round, and
  every model's wounds and position). Rebuilding the initial state from scenario + seed keeps replay
  files valid when later milestones add state fields; `expect` compares only what the replay is
  about.
- Replay regression test: every file must run with every step valid and match its `expect` block.
- **M94 (D-095):** format 2 records each dice roll as a `RollDice` step (the engine paced); format 1 (every roll
  inside its step) still runs. The saved replays are format 2 since M94.
- **M95 (D-096):** format 3 records each reaction window's answer as a step (`DeclineStratagems` or `UseStratagem`),
  and a random D per damaging attack. Formats 1 and 2 still load (converted step by step); the saved replays are
  format 3 since M95.
- **M96 (D-097):** format 4 also records the answers to the windows that follow no roll (15.08, 15.11, 15.12); a
  format-3 file is converted by declining them. The saved replays are format 4 since M96.
- **M97 (D-099):** format 5 also records the answers to the windows just after a charge move (15.06 Crushing Impact)
  and what they lead to; a format-4 file is converted by declining them before each recorded step and at the end
  (format 3 declines D-097's too). The saved replays are format 5 since M97.
